Known limitations¶

Command restrictions¶

These describe the current interface, not a list of new removals. See Changelog for changes from 2.2.0 and replacement workflows.

  • Identity: use full UUIDs or tags; short UUID prefixes are unreliable for jail lookup. Image import separately supports unique image prefixes.

  • Defaults: saved defaults apply to later ordinary create commands, not existing, cloned or imported jails. reset does not reload saved creation defaults. get all default does not dump them; use defaults.

  • Fetch: release availability depends on the selected mirror/path. Failed preparation retains datasets/downloads; inspect incomplete releases and cached archives before retrying. Existing prepared releases are patched, not re-extracted. Processing an existing release requires all iocell jails on the host to be stopped, including thick jails and those on other releases or pools. An incomplete release is refused on retry; see Basic usage for per-release manual recovery. Obsolete ports options are rejected; manage a modern ports tree separately with Git.

  • Deactivation: deactivate prints manual removal guidance; it does not clear the native pool discovery comment or disable existing jails.

  • Imports: ordinary streams reject property operands; set properties after restoring. Legacy archives retain their property-aware creation path. Incomplete .partial images are not candidates. Failed receives/extractions retain the image and any partial datasets; inspect them before retrying.

  • Image format: ordinary exports are raw recursive ZFS streams, not an archive/checksum pair. Legacy thick-jail archives use a separate import path; not every image format supplies or verifies SHA256 sidecars.

  • Arguments: quote property values for the invoking shell; create and set preserve them literally.

  • Runtime errors: syntax errors fail before initialization, but valid multi-target commands are not transactional. Property/kernel validation and runtime status propagation remain incomplete.

  • Git: automatic plugin release branches retain tracking upstreams. Explicit tag/commit checkouts may intentionally detach HEAD. Experimental push is disabled before initialization and in its backend. The old implementation operated in the caller’s working directory and could stage unrelated files or push the wrong repository. Use Git directly in an explicitly selected worktree; iocell does not supply a replacement deployment/push command.

  • Legacy names: chroot, record, package and show were already undispatched in 2.2.0. Old create -b/-c/-t and base= recipes were also unsupported; correcting the examples removes no working modes. See Jail images and historical differential packages for the available image workflow.

  • Altroots: selection follows the selected dataset’s actual mounted path, not the presence of another /iocell directory. Changing the persisted library root selector requires root and writable libraries; unchanged read-only queries do not rewrite it. Newline-containing mountpoints are refused.

Storage boundaries¶

Ordinary basejail upgrades require complete release sources, a stopped jail and no preexisting mounts below its root. In-place upgrade of a template-based basejail is refused; use a target-release template instead. Build/merge failures restore the old config/root where possible and retain etc.old, the root upgrade snapshot and the single overwritten config.old backup. An incomplete backout is reported; inspect recovery objects before retrying. A failed merge’s log is copied to upgrade.log before rollback when available. Warnings alone are not merge failures; unresolved conflicts are. Independent-userland upgrades remain a separate workflow and can require interactive installation passes.

Basejails share read-only release directories. create -e supplies an empty filesystem, not a clone or independent OS. Changing a type label does not copy an OS tree. Shared-release updates affect every basejail using that release; back it up separately and use a maintenance window.

Template conversion requires a safe dataset tag; generated timestamp tags containing @ must be retagged first. A failed rename preserves metadata and delegated state. A later metadata or alias failure is reported, but the dataset may already have moved. clean -t removes the whole templates tree, including internal clones; only explicit force permits destruction of outside clones.

A full receive can be refused by ZFS when the destination already has snapshots. Use incremental streams or a fresh destination, not an automatic destructive replacement. Remote sends validate their destination on the receiver. Remote -c cleans only sender retention; manage receiver snapshots separately. Cleanup removes older reserved ioc-send-* snapshots after success, keeping the new replication point and never deleting dependent clones. Failed full transfers retain and name their source snapshot for recovery.

Normal snapshots cover root only; recursive snapshots include configuration and descendants. Rollback does not restore native properties, tag links or the shared release. The saved tag can differ from current aliases. New descendants can block recursive rollback; multi-dataset rollback can stop after earlier targets have already been restored. Take application-consistent backups separately.

Kernel and networking notes¶

VNET needs VIMAGE support; RACCT/RCTL are required only for resource limits. A stored property does not prove that the host kernel applied it. Consult jail(8), zfs(8) and rctl(8) for the host version.

The old 88-character mount-path issue and hack88 workaround concern historic kernels. Do not enable it as a general prerequisite. Likewise, old FreeBSD 10 VNET/PF/ALTQ reports are not blanket descriptions of current kernels.

IPv6 services can race address readiness during startup. Diagnose address and service ordering rather than globally disabling duplicate-address detection: net.inet6.ip6.dad_count=0 affects the host as well as its jails.
