# Five high-risk fixes — 2026-10-30

This follows the [historical command audit](command-audit-2026-10-29.md).
It records targeted safety verification, not a rerun or reclassification of
all 335 audit cases. Other functional/documentation findings remain open.

## Changes

1. **Move safety:** capture the original source dataset before activation can
   change global pool state. Mount/select the real received configuration,
   propagate transfer/activation/mount failures, verify destination selection,
   then destroy only the original source. Local self-send is rejected;
   identical pool names on different hosts remain valid.
2. **Fresh full sends:** use a unique snapshot for every operation and stop if
   snapshot creation fails. Check sender, receiver and both optional buffer
   statuses, rather than just the last pipeline process. Clean-send snapshot
   creation occurs after pre-send cleanup.
3. **Discovery safety:** discover direct jail/template children, not arbitrary
   descendants. Nested update backups cannot trigger parent regeneration.
   Existing configs are never regenerated by the migration helper; genuine
   missing legacy configs still migrate. Names containing `base` no longer
   disappear because of substring filtering.
4. **Template safety:** validate the destination tag and clone dependencies
   before mutation. Rename before metadata/alias updates; restore delegated
   state on rename failure and preserve both on/off states. Reject invalid
   config paths, propagate UCL errors, and keep an existing config in place
   while preparing its replacement. Shared dependency-query errors also stop
   destruction callers, not only conversion.
5. **Template cleanup safety:** inspect native clone origins, including root
   datasets and clones outside the jails namespace. Non-force cleanup leaves
   ZFS's external-clone protection enabled, covering clones created after
   preflight. Only explicit force allows recursive dependent destruction.
   Cleanup/query failures propagate through the CLI.

Generated timestamp tags contain `@`: conversion now fails safely and requires
explicit retagging, e.g. `iocell set tag=mytemplate UUID`. It does not silently
change the tag or introduce a new template dataset layout. A config-write error
is reported; this is not a claim of an atomic transaction across every ZFS and
configuration operation.

## Verification

- **88 portable scenarios under `sh`, and 88 under `dash`: all passed.**
  New tests were observed failing on the relevant unsafe behavior before its
  production fix. They cover pipeline failures, immutable move identity,
  activation failures, discovery, migration, forward/back conversion, config
  writer failures, clone races and dependency-query error consumers.
- **44 native FreeBSD/ZFS verification groups: all passed.** These comprise
  20 safety groups, the existing 6 package-creation, 7 template round-trip and
  6 rollback scenarios, plus 5 real remote replication groups.
- Native probes compare file contents, exact config bytes, dataset GUIDs,
  delegated state, aliases, active-pool configuration and snapshot presence.
- Failure injection includes snapshot creation, a sender failing after writing
  a complete real stream, receiver failure, actual activation failure, rename
  failure, origin-query failure, and a clone created immediately before ZFS
  destruction. A controlled `/config` sentinel stayed byte-identical.
- Both plain SSH and **real mbuffer on both hosts** passed full, `-i` and `-I`
  transfers. Real local/remote buffers reporting failure after a completed
  stream produced nonzero status and retained the source.
- Package tests install a real package; returned template jails were actually
  started, executed commands, and stopped. Syntax and `git diff --check` passed.

Host: FreeBSD 15.1-RELEASE-p6, amd64. The private receiver was temporarily given
2 GiB for the existing 1 GiB buffers; its original memory configuration is
restored after verification. No VM definition or VM disk is deleted.

See [tests/README.md](../tests/README.md) for commands and requirements. The
combined native log and portable logs are retained on the test host under
`/vms/iocell-test/safety-fixes/`; native fixture/log paths are printed by each
script. Scratch pools/file vdevs are retained separately from the VM disks.

## Explicit limits

- Full-stream native tests use fresh receiver namespaces. ZFS can reject a
  full receive into an existing snapshot-bearing replica; use incremental
  streams or explicitly prepare a fresh destination. No automatic destructive
  replacement was added to make this test pass.
- The pre-existing remote-pool validation issue is separate: remote tests
  provision a matching local pool name, and report that workaround explicitly.
- This does not qualify other FreeBSD host versions, architectures, all
  property combinations, or application/database-level snapshot consistency.
- The earlier audit's 52 failing checks are historical results, not a claimed
  current failure count. In particular, an unsafe generated template tag now
  intentionally returns an error rather than being converted automatically.
